# 存储策略

更新时间：2026-10-23

## 1. 决策

Open Sales Assistant 保留 JSON 文件存储作为默认轻量模式，并支持 PostgreSQL 作为可选存储。

默认模式：

```env
STORAGE_DRIVER=json
```

当前支持的可选模式：

```env
STORAGE_DRIVER=postgres
```

MySQL 暂未实现。

## 2. 为什么保留 JSON 存储

JSON 存储适合作为开源基础版本，因为：

- 新用户克隆仓库后不需要安装数据库就能运行。
- Demo 数据容易查看、重置和通过 Git 审阅。
- 小团队可以先验证工作流，再决定是否引入生产数据库。
- 贡献者可以用最少环境复现问题和运行测试。
- 对不熟悉服务器和数据库的用户更友好。

JSON 写入通过单进程互斥锁串行执行，适合本地演示和单实例小范围试用。不要用多个 Node.js 进程或多个容器共享同一个 JSON 文件。

## 3. 当前存储实现

存储接口位于 `server/storage/`，应用通过统一的 `readDb()`、`writeDb()` 和事务生命周期访问数据。

PostgreSQL 当前将全量应用状态保存为 `open_sales_assistant_state` 表中的单个 JSONB 文档。每个写请求在事务中锁定该行，再提交修改，保证多实例写入不会覆盖彼此。该实现保留了已有 JSON 数据结构，便于早期小团队试点迁移。

所有写入共享一把数据库行锁，AI 生成、聊天等耗时写请求也会占用锁。数据量、查询量或并发写入增加后，应把线索、成员、活动和操作日志拆成关系表，再逐步迁移读写查询。

## 4. 适配器结构

当前 adapter 结构：

```text
server/storage/
  index.js
  json-store.js
  postgres-store.js
```

当前应用层调用统一的 storage 方法，JSON 文件操作集中在 JSON adapter 中。

当前接口包括：

- `readDb()`
- `writeDb(db, options)`
- `createBackup(reason)`
- `transaction(callback)`
- `healthCheck()`
- `close()`

## 5. JSON 与 PostgreSQL 迁移

设置 `.env` 中的 PostgreSQL 连接：

```env
STORAGE_DRIVER=postgres
DATABASE_URL=postgresql://sales_app:替换为安全密码@localhost:5432/open_sales_assistant
```

然后把现有 JSON 数据导入空 PostgreSQL 数据库：

```bash
npm run migrate:postgres -- --file data/db.json
```

也可以传入后台导出的 JSON 文件。若目标库已有数据，脚本会拒绝覆盖；确认目标数据可以替换后，再显式添加 `--replace`。导入时会清除旧登录会话，管理员需要重新登录。脚本会在替换非空目标前创建备份。

PostgreSQL 模式的手动备份和每日备份会写入 `DATA_BACKUP_DIR`，格式为 JSON。恢复时停止应用并用备份文件执行 `npm run migrate:postgres -- --file <备份路径> --replace`，然后重新启动。

## 6. 兼容规则

任何数据库相关开发都必须遵守：

- 不移除 JSON 存储。
- `npm test` 不依赖数据库。
- 默认 quick start 不依赖数据库。
- PostgreSQL 写入由数据库事务行锁串行化；JSON 锁只覆盖单个 Node.js 进程。
- 不提交本地生产数据。
- demo 数据仍然可以通过 Git 或 fixture 重置。
- 文档必须说明什么时候 JSON 足够，什么时候建议数据库。

## 7. 什么时候用哪种模式

适合使用 JSON：

- 本地试用项目。
- 测试 demo 数据。
- 开发新功能。
- 小规模内部 proof of concept。

适合使用 PostgreSQL：

- 多个团队成员同时写入数据。
- 需要更可靠的备份、恢复、审计和迁移。
- 准备生产部署。
- 需要更大规模的报表、分析或外部系统集成。

PostgreSQL 当前适合低到中等写入量的小团队试点。大数据量、高并发和复杂报表需要后续关系型表迁移。

## 8. 团队角色

- `super_admin`：管理成员、导出和备份数据，并拥有全部线索权限。
- `manager`：查看和分配本团队线索，维护其他业务模块。
- `sales_rep`：查看和跟进分配给自己的线索，不能删除线索或访问其他后台模块。

当前使用单团队 `team_default`，尚未实现多租户隔离。
