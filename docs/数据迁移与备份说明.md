# 数据迁移与备份说明

更新时间：2026-10-23

## 1. 当前数据方式

默认模式使用本地 JSON 数据库：

```text
data/db.json
```

JSON 模式适合 demo、单实例小团队试用。其互斥锁只覆盖当前 Node.js 进程。

多人试点可使用 PostgreSQL。当前 PostgreSQL adapter 将应用状态保存在 `open_sales_assistant_state` 的 JSONB 文档中，事务行锁会串行化应用写入。所有写请求共用这一行锁，因此高频写入和较慢的 AI 写请求会产生排队；更大规模使用前需迁移到关系表。

## 2. 数据版本

当前数据版本：

```text
schemaVersion = 4
```

服务启动和读取数据时会补齐旧数据缺失字段，并在迁移前生成备份。v4 增加管理员角色、团队 ID 和线索负责人 ID。

## 3. 自动备份

默认备份目录：

```text
data/backups/
```

每次写入前，系统会检查当天是否已有每日备份：

```text
data/backups/YYYY-MM-DD-daily.json
```

如果发生自动迁移，会生成迁移前备份：

```text
data/backups/时间戳-before-migration.json
```

## 4. 自定义备份目录

可在 `.env` 中配置项目外备份目录：

```env
DATA_BACKUP_DIR=/opt/open-sales-assistant-backups
```

生产或长期试用时，建议把备份目录放到项目目录外，避免更新代码时误删。

JSON 和 PostgreSQL 模式都把逻辑备份写成 JSON 文件。生产部署应定期把 `DATA_BACKUP_DIR` 复制到独立的备份位置。

## 5. 导出和手动备份

后台导出：

```text
GET /api/admin/data/export
```

后台手动备份：

```text
POST /api/admin/data/backup
```

两个接口都要求管理员登录。

## 6. 开源仓库注意事项

不要提交：

- `.env`
- `uploads/`
- `data/backups/`
- 真实客户数据
- API key、token、密码

允许提交：

- `data/db.json` 中的安全 demo 数据
- `.env.example`
- 数据结构和迁移说明

## 7. 恢复数据

1. 停止 Node 服务。
2. 找到目标备份文件。
3. 将备份文件复制为 `data/db.json`。
4. 启动 Node 服务。
5. 系统会自动检查数据版本并补齐字段。

恢复前建议先保存当前 `data/db.json`。

## 8. 导入到 PostgreSQL 与恢复 PostgreSQL

1. 创建空 PostgreSQL 数据库，并在 `.env` 设置 `STORAGE_DRIVER=postgres` 和 `DATABASE_URL`。
2. 停止应用，保留原始 `data/db.json`，再运行：

   ```bash
   npm run migrate:postgres -- --file data/db.json
   ```

3. 启动应用并验证账号、线索和沟通记录。

目标数据库非空时命令会拒绝导入。确认可以替换全部目标数据后使用 `--replace`；脚本会先备份非空目标。导入会清除已有管理员会话，之后需要重新登录。

从 PostgreSQL JSON 备份恢复时，停止应用并使用：

```bash
npm run migrate:postgres -- --file data/backups/<备份文件>.json --replace
```

此命令会把备份中的状态写回 PostgreSQL。执行前请确认 `DATABASE_URL` 指向正确的数据库。
