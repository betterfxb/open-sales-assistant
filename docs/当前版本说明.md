# 当前版本说明

更新时间：2026-10-23

## 1. 当前版本定位

当前版本是 Open Sales Assistant 的开源初始版本。它面向团队和个人销售自部署使用，重点提供销售知识库、客户咨询入口、AI 辅助问答、客户画像和基础跟进记录。

当前适合：

- 本地试用和开源 demo。
- 小团队内部自部署。
- 用真实销售资料搭建知识库。
- 验证 AI 辅助销售咨询和跟进流程。

当前不适合：

- 高并发生产环境。
- 大型团队复杂权限管理。
- 多组织托管运营。
- 直接处理未脱敏客户隐私数据。

## 2. 访问入口

| 页面 | 本地地址 | 说明 |
| --- | --- | --- |
| 客户咨询 | `http://localhost:3100/` | 昵称注册、聊天问答、证书查询、个人中心 |
| 后台登录 | `http://localhost:3100/login.html` | 管理员账号密码登录 |
| 后台管理 | `http://localhost:3100/admin.html` | 线索工作台、团队成员、知识库、客户、素材、配置和操作日志 |
| 健康检查 | `http://localhost:3100/api/health` | 服务状态 |

## 3. AI 配置

默认使用 OpenAI-compatible `/chat/completions` API 配置方式。使用者需要复制 `.env.example` 为 `.env`，并填写自己的 `AI_API_KEY`。项目不会把 API Key 存入后台 UI 或 `data/db.json`。

```env
AI_PROVIDER=kimi
AI_BASE_URL=https://api.moonshot.cn/v1
AI_API_KEY=请替换为你自己的 API Key
AI_TEXT_MODEL=kimi-k2.6
AI_VISION_MODEL=kimi-k2.6
```

如果暂时不配置 `AI_API_KEY`，部分流程会使用本地兜底内容，便于验证页面和数据流程。

可替换服务商示例：

- Kimi：`AI_BASE_URL=https://api.moonshot.cn/v1`，模型 `kimi-k2.6`。
- OpenAI：`AI_BASE_URL=https://api.openai.com/v1`，模型按账号可用模型填写。
- DeepSeek：`AI_BASE_URL=https://api.deepseek.com`，模型可填写 `deepseek-chat`。
- DashScope：`AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`，模型可填写 `qwen-plus`。

`/api/health` 只返回 `aiConfigured` 和模型名，不返回 API Key。

## 4. Demo 数据

`data/db.json` 保留英文课程销售场景 demo 数据。

注意：

- 这些数据只用于演示知识库、销售话术、FAQ、顾虑应对和聊天历史结构。
- 正式使用前应替换成自己的产品、服务、价格、FAQ 和合规规则。
- 不要把真实客户隐私数据提交到公开仓库。

## 5. 当前数据存储

默认使用本地 JSON 文件；也可配置 PostgreSQL：

```text
data/db.json
```

上传文件目录：

```text
uploads/
```

默认备份目录：

```text
data/backups/
```

`.gitignore` 已排除 `.env`、`uploads/` 和 `data/backups/`。

JSON 适合本地 demo 和单实例轻量自部署。PostgreSQL 适合单团队低到中等写入量的多人试点；当前将完整状态存为单条 JSONB 记录并串行化写入。更高并发和复杂报表需要迁移为关系表。MySQL 尚未实现。

当前已提供 Dockerfile 和 Docker Compose 部署方式，方便容器化自部署。

## 6. 主要不足

- 已支持超级管理员、主管和销售三种角色；销售线索支持负责人、跟进提醒和团队内权限。
- 当前仅支持单团队，不支持多组织隔离或大型团队的精细权限。
- 已有基础操作日志，用于记录关键后台写操作。
- AI 生成的知识建议可在采纳前审核和修改。
- 中英文销售回复基线评测无需 API Key 即可运行，并提供可选的真实 AI 评测模式。
- 暂无知识库版本回滚。
- 暂无 AI 用量和成本统计。
- JSON 文件不适合多人高并发写入。
